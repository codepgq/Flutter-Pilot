# Flutter API Mocks 项目记忆

## 已完成头脑风暴并确认的需求

- macOS 上的 VS Code/Cursor 桌面扩展，Android/iOS Dio 5 优先。
- 代理路线优先零代码；系统代理/证书不兼容时提供开发期最小辅助代码和可预览、可撤销补丁。
- 插件管理固定版本 mitmproxy 独立引擎，不依赖用户 Python。
- 请求、响应规则修改，本地 mock，目标地址改写（不是 301/302）。
- 自动规则及双向人工断点；默认超时 60 秒自动放行。
- 请求历史与 mock 规则分开；历史事实不直接改写，备注标签可改，规则支持 CRUD。
- 默认历史 7 天 / 10,000 条 / 正文 1 MiB；最新确认规则放项目目录，SQLite 按项目身份与工作区目录保存在 IDE 私有存储。
- 2026-11-08 用户确认后台记录，关闭工作台仍继续；最新默认 VM，首次输入 WS 后记录。代理模式仍需先完成引擎安装及 Flutter 接入。
- API 目录独立持久化，按方法、主机、路径保存累计调用数及首次 / 最近调用时间；历史清理不影响目录，可手动删除，后续请求重新发现。
- autoStart 默认 true，手动停止本会话后不因重新打开面板恢复；下次打开 IDE / 工作区按设置启动。
- 2026-11-08 用户确认 API 工作台优化：API 目录按最近调用、请求历史按发生时间从新到旧；目录可折叠；点击请求便于查看 Request / Response，响应优先尝试 JSON 解析。允许补充相关布局与使用体验优化。
- 规则启停不能看起来像禁用控件；最新反馈要求仅保留简洁 switch，去掉“已启用 / 已停用”和点击说明文字，保留明显滑块、悬停和键盘焦点，停用规则不整体降低透明度。
- 关闭面板仅释放等待断点并关闭人工暂停；后台继续执行已启用自动规则及记录。退出 IDE / 移除工作区才关闭会话。
- 不开放任意脚本，不承诺支持 pinning、自定义适配器、Web、Remote SSH 或所有网络库。

## 工程约定

- 扩展 TypeScript，工作台 React，代理 Python addon，管理通道本机 TCP JSONL v1 + 会话令牌。
- 文件按 src/、webview/、proxy/、tests/、examples/flutter/ 分工。
- 规则按原始请求匹配；每阶段最高优先级首条执行，列表稳定排序；手工编辑最后执行。
- 必须保留证书校验，禁止 badCertificateCallback 无条件放行。
- 用户已授权完整实现本计划，不重复询问已确认需求。
- 真实设备或 IDE 无法验收的项目标注未验证，不能冒充通过。

## 实际项目接入记录入口

- EXIO 已完成 Cursor + iPhone 18 Pro 模拟器实际接入。配置、操作截图、Mock 演示和恢复步骤见 [EXIO 图文教程](../../docs/exio-cursor-guide/README.md)，实际通过范围见 [验收记录](../../docs/validation.md)。
- Dart workspace 根目录即使没有直接声明 Flutter，也应根据显式 workspace 成员识别 Flutter 项目，并以 IDE 根目录维护一个后台会话；不递归扫描、不展开 glob，最多检查 256 项。
- 遇到自定义 Dio 适配器时先检查项目已有开发接入口；EXIO 通过独立开发入口复用 API installer，加入当前代理 CA 公钥证书并保留 TLS 校验，不沿用无条件放行证书的代理设置。

## 0.0.2 VM Service 需求与头脑风暴结论（2026-11-08）

- 用户要求验证“只提供 Flutter 运行时 VM WS、无需改源码完成 API 记录与 Mock”的可行性，作为 0.0.2 feature，新建分支并测试完善；分支为 `codex/v0.0.2-vm-service`。
- 先验证观察与修改的区别：SDK HTTP profiling 能采集，Mock 需 Debug/JIT 对象发现和运行时安装 Dio 拦截器；已真实验证这一方案。不能把 VM profiling 描述成可直接改请求。
- 最新用户确认：VM WS 为默认且首要接入方式，代理作为备用和兜底。新工作区默认 VM，即使有可用引擎也不启动代理；已有工作区沿用保存的方式，旧版无 mode 的代理配置保留。VM 默认仅记录，运行时 Mock 必须显式开启。不写入应用源码、不安装 CA、不覆盖应用 adapter/TLS。
- VM 会话与工作台分离，关闭工作台继续记录；WS 认证地址只保存在会话内存，重开 IDE 需重新输入。
- 用户确认 VM 状态交互：连接中禁用输入与重复连接；成功后明显显示“已连接 · 当前端点”，禁用地址输入，仅保留断开操作。换地址先断开；失败或断开不能残留旧端点作为当前连接。
- VM 与代理共用规则，API 目录和历史分库，VM 历史不依赖引擎。沿用独立 API 目录、历史事实不改写和规则草稿机制。
- VM 不支持人工断点，需使用代理；不承诺 Profile/Release、所有网络库、Dio 版本或自定义拦截链。
- 用户指定版本号 0.0.2 比旧版 0.1.0 小，覆盖安装需要 `--force`；不擅自改成 0.1.1。
- VM 真实 Flutter 验收为 iPhone 18 Pro / iOS 27.2 模拟器，源码 SHA 未变、无代理/helper/CA；尚未通过 Android 和 iOS 真机 VM 验收，EXIO MFA 问题未修复。详见 `docs/v0.0.2-vm-service.md` 与 `docs/validation.md`。

## 项目 UUID 绑定确认（2026-11-08）

- 用户确认：UUID、项目配置和 Mock 规则都放在项目目录，分别使用 `.api-mocks/project.json` 和 `.api-mocks/rules.json`；运行时历史、CA 私钥及 VM WS 不写入项目。
- 同一 UUID 的多个目录或 Git worktree 各自记录历史，规则从各自目录文件读取，不共享 SQLite 或后台代理会话。
- 配置文件格式带 version，项目 UUID 首次生成、后续复用；已有项目文件优先，旧私有规则和连接配置只在目的不存在时导入，保留源文件。
- 项目设置覆盖对应 IDE 设置，未指定值回退 IDE；编辑后需按工作台入口重新读取，运行参数生效时机按文档说明。
- 移动目录不改变项目文件中的 UUID，但不承诺跨路径自动接续本机历史。是否把 `.api-mocks/` 纳入 Git 由用户决定，插件不自动 git add 或提交。
