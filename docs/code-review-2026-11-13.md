### 1. 代理断线切换场景后旧规则可能继续生效

**位置：** `src/engine.ts:218`、`src/extension.ts:331`、`src/extension.ts:359`、`src/scene-controller.ts:229`、`proxy/addon.py:139`。

控制连接断开后引擎状态变为 error，但代理进程保留既有规则。此时切换场景，HTTP 卸载仅在引擎为 running 时执行，控制器仍记录新场景的 `appliedKey`，而该 key 未包含引擎连接状态。重连后若其他 key 字段不变，`reconcile` 直接跳过；状态又以代理活动且无同步错误判断为已应用。结果可能是界面显示场景 B 已应用，实际仍执行场景 A 的规则。

**验证：** 使用真实 `SceneController` 与模拟宿主按 A 生效 → 断连 → 激活 B → 重连 → reconcile 执行，得到 `active=B, actual=[A], status=applied`。这是控制器层模拟，不代表已完成真实 mitmproxy 故障注入。

**建议：** 将控制连接代次或状态纳入失效条件；断连时明确标记运行态未知并在恢复后强制先卸载再同步当前场景。补充真实控制连接断线、断线期间切换及停用场景的回归测试。

### 2. JSON 格式化改变业务数据

**位置：** `webview/main.tsx:194`、`webview/main.tsx:215`；现有保留原始 token 的只读格式化逻辑位于 `webview/body.ts:1`。

编辑器的“格式化 JSON”先解析再序列化。输入 `{"id":9007199254740993,"x":1,"x":2}` 后得到 `{"id":9007199254740992,"x":2}`：大整数被舍入，重复键被丢弃。该编辑器覆盖规则 JSON、请求/响应正文及断点正文；用户格式化并保存或放行后可能发送改变的数据。

**建议：** 使用能保留原始数字、重复键和字符串转义的格式化实现，非法或超限时保留原文并提示；增加规则与断点编辑器的端到端回归测试。

### 3. API 目录持续增长可能阻断刷新

**位置：** `proxy/storage.py:91`、`src/vm/storage.ts:65`、`src/vm/storage.ts:221`、`src/extension.ts:1019`、`proxy/addon.py:89`。

API 目录不随历史保留策略清理，代理和 VM 均一次读取全部目录项；VM SQLite 输出受 128 MiB 限制，代理响应受控制帧限制。目录足够大或路径较长时，查询可能超过限制。`reloadHistory` 使用 `Promise.all` 同时获取历史和目录，目录失败会使正常历史结果也无法更新。

**建议：** 为目录增加服务端分页及筛选，将历史和目录刷新错误隔离；测试长路径、大量不同 API、删除后恢复及代理/VM 两种模式。该问题的实际触发条数取决于数据大小，本次未进行容量压力测试。

### 4. MCP 服务版本声明过期

**位置：** `src/mcp/bridge.ts:31`、`package.json:6`、`tests/mcp-transport.test.ts:93`。

MCP 初始化声明 `0.0.12`，项目版本为 `0.0.13`。客户端据此诊断或显示版本时会得到错误信息；现有握手测试只检查服务名称。

**建议：** 从单一版本来源生成服务声明，并在 MCP 握手测试中校验与发布版本一致。
