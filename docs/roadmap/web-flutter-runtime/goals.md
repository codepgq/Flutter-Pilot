# 最终目标与支持范围

验收基线：v1，2026-11-16。每个目标必须由下列阶段的实际报告证明，历史 Flutter 成功记录不能替代本次改造后的复验。

## 最终目标

| ID  | 最终行为                                                                                                         | 完成依据                         |
| --- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| G01 | 一个仓库、一个 IDE 插件、默认一个 MCP 服务，同时发现并操作 Flutter 与 Web 的明确运行目标                         | phase-01、03、07                 |
| G02 | 保留现有扩展 ID、`flutter-pilot` MCP 服务名、项目 UUID、`.flutter-pilot/` 路径、Scene v2 和已有 Flutter 调用兼容 | phase-01、07                     |
| G03 | 普通 Web 项目可显式接入并被识别，HTTP/HTTPS 代理模式可由工作台及 MCP 配置、查询与验证                            | phase-02、07                     |
| G04 | 独立浏览器 Worker 按需准备依赖；托管 Context 在首次导航前安装 HTTP 拦截，正常转发或执行 Scene Mock               | phase-03、07                     |
| G05 | Web 使用稳定 DOM 选择器执行输入、点击、等待、滚动及截图，可保存并复用 Scene actions                              | phase-04、07                     |
| G06 | Web WS/WSS 可采集、替换、丢弃，向明确连接发送或注入消息，并记录实际处理结果                                      | phase-05、07                     |
| G07 | Test Case v2 可运行 Web 业务流程，以本轮 HTTP、关联 WS 与最终 UI 判断成功、失败、取消和未确认                    | phase-06、07                     |
| G08 | 多项目、同项目多运行时及多 Context 的激活、历史、临时状态与锁隔离，Worker 故障不影响 Flutter 会话                | phase-01、02、03、04、05、06、07 |
| G09 | 共享工具按能力分发；所有新增/调整工具同步 schema、同名 Prompt、场景 Prompt、离线指南和能力导航                   | phase-01、02、03、04、05、06、07 |
| G10 | 通过真实浏览器、Flutter 回归与一个实际 Agent 客户端验收，记录源码、环境、限制和分发验证；不扩大支持声明          | phase-07                         |

最终完成 = 七个 phase 全部 `passed` + G01–G10 的报告映射完整 + 无未恢复测试环境或本轮泄漏进程。仅 HTTP Mock 可用、仅动作 completed、仅 SDK 握手或仅打包成功均不等于最终完成。

## 首轮范围

| 对象           | 本轮承诺                                                                     | 验收边界                                                                                          |
| -------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| IDE / 操作系统 | 保持当前 macOS 本地 VS Code / Cursor 运行范围                                | 不据此宣称 Windows、Linux、SSH、容器或远程扩展宿主通过                                            |
| Flutter Debug  | 保留 VM / Dio、HTTP 代理和已有原生设备能力                                   | 新代码真实回归使用独立 iOS 模拟器；Android / 真机状态分别报告，不借此扩展历史承诺                 |
| 普通 Web       | Chromium 托管浏览器中的标准 DOM 项目；原生 HTML、React、Vue 提供可运行夹具   | 业务框架只负责生成页面，不注入 React/Vue 私有运行时                                               |
| Web 项目发现   | 显式注册本地 URL；识别 React / Vue / Vite 等已知声明；支持显式选择子项目根   | package.json 存在不等于 Web 项目；混合仓库不强制归成单一类型                                      |
| HTTP / HTTPS   | JSON / 文本请求、响应、规则命中、正常转发；代理与浏览器拦截分别验证          | 两种后端明确选择，同一请求不叠加两套 Mock；CORS、预检、证书与缓存策略有独立证据                   |
| WebSocket      | 浏览器目标 URL 的文本 WS/WSS，连接注册后采集与规则处理                       | Worker 接入前的连接/消息不可补抓；开发服务器 HMR socket 默认不纳入业务规则                        |
| UI / 截图      | 稳定 testId、显式 role/name、frame 范围，输入/点击/等待/滚动，视口和整页截图 | 复杂手势、系统 UI、原生权限、浏览器工具栏不在 Web UI 承诺内                                       |
| 多端业务       | 同一 MCP 可分别驱动 Flutter 和 Web，复用接口规则与业务断言模型               | 两端 UI targets/actions 分别定义；单个 Test Run 固定一个运行时，跨端分布式事务编排不在本轮范围    |
| Flutter Web    | 浏览器层 HTTP/WS 可走 Web 接入                                               | 不复用 Dart VM 注入；Canvas/语义层 UI、Widget Key 映射不在本轮范围，不宣称 Flutter Web 全功能支持 |

## 本轮不交付

- 新插件、新代码仓库、第二个默认 MCP 服务、品牌/配置路径迁移。
- 脱离 IDE 的独立产品、CI 服务、远程共享浏览器及多用户服务。
- 附着用户日常浏览器 Profile、任意 CDP 实例、Firefox、WebKit、移动浏览器矩阵。
- Next.js/Nuxt 的服务端 SSR、Node 后台任务及其他非浏览器进程请求 Mock；它们的浏览器端请求仍按 Web 范围处理。
- Service Worker / PWA 离线运行的透明全覆盖；托管测试 Context 的默认策略是阻止 Service Worker，并明确展示这一差异。
- SSE/流式正文编辑、二进制 WS Mock、录制生成动作、任意 JavaScript MCP 执行器。
- 扩展商店发布、自动推送、自动安装、重载活动 IDE、清理用户浏览器数据。

## 范围变更

新增平台、放宽必需验收或移动功能到后续版本时，先在 [verification.md](verification.md) 的变更记录说明原因、受影响目标/条款和新的验收安排，并增加基线版本。不得把缺环境的必需项改成可选来获得通过。
