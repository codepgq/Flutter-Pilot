# phase-05：WebSocket 采集与 Mock

依赖：phase-04 passed。目标：G06、G08、G09。验收基线：v1。

## 阶段目标

在明确的浏览器运行时中采集业务 WS/WSS 文本消息，复用已有规则的替换/丢弃语义和 MCP 发送/注入工具，明确接入时点与连接边界。

## 任务与产出

- [x] P05-T01：为新建业务 WS 在页面创建前安装路由，维护运行时/Context/Page/连接 ID 与状态。
- [x] P05-T02：复用 WS 规则验证和匹配，实现双向原始/有效消息、替换/丢弃及查询。
- [x] P05-T03：实现向 App 注入与向真实服务端发送，保持方向、synthetic 标记、唯一连接与容量限制。
- [x] P05-T04：增加 WS/WSS、并发同 URL、重连、二进制限制及 HMR 对照夹具和 `test:web:ws`。
- [x] P05-T05：更新工作台、能力状态、同名 Prompt、WS 场景指南与验收。

主要落点：Web Worker、Web Adapter、`src/ws/`、MCP network、Scene runtime 分域能力以及工作台 WS 页面。

## 固定验收标准

| ID      | 必需预期                                                                                                                | 验证方式                               |
| ------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| P05-A01 | 本地 WS/WSS 的入站/出站文本记录含准确 URL、目标、连接 ID、方向、原始/有效正文；TLS 正常验证；不把 HMR socket 当业务连接 | 真实 WS/WSS 夹具和查询对照             |
| P05-A02 | 同一 Scene 的 replace/drop 依优先级和方向只作用于匹配消息，非匹配消息直通，丢弃不抵达对端且记录 outcome 正确            | 页面/服务端收件计数与规则证据          |
| P05-A03 | inject_ws_message 仅投递到目标页面并记录 synthetic，服务端未收到；send_ws_message 使用既有真实连接并经过 outbound 规则  | 三端计数与 MCP 调用结果                |
| P05-A04 | 两 Context 同 URL、单页多连接及关闭重连后不串连接；失效/歧义 ID 拒绝，取消或未确认不重发；旧消息不能被重连补抓          | 多连接/重连与取消反例                  |
| P05-A05 | 能力明确仅覆盖路由注册后的连接；接入前连接不标 attached，激活/reload 不隐式刷新或重连页面；必要的新连接由显式动作产生   | 注册前后对照、生命周期计数             |
| P05-A06 | 二进制与超限消息明确直通或拒绝编辑，不能损坏原流；关闭采集同时暂停该域 Mock，恢复规则行为可验证，其他运行时不受影响     | 容量/类型/开关反例                     |
| P05-A07 | 生产 WS schema、工作台、MCP 同名/场景 Prompt 与能力导航一致；旧 Flutter WS 回归通过，代理 WS 仍如实报告 unsupported     | 协议、规则单元、UI 与 Flutter 相关回归 |
