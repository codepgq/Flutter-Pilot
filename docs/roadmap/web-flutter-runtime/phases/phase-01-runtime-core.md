# phase-01：运行时核心与代理路由修复

依赖：无。目标：G01、G02、G08、G09。验收基线：v1。当前状态见 [progress.json](../progress.json)。

## 阶段目标

把项目、运行目标和网络/UI 能力从 Flutter 实现中分离，修复现有 MCP 在代理模式查询 VM 历史的问题，为 Web 接入提供可验证的基础。此阶段不宣称新增浏览器能力。

## 任务与产出

- [x] P01-T01：记录目标身份、Adapter 最小接口、能力和错误语义；区分项目、运行时、设备/页面作用域。
- [x] P01-T02：为现有 VM 与代理增加适配边界，统一工作台和 MCP 的 HTTP 列表、详情及采集/Mock 状态路由。
- [x] P01-T03：将激活、历史、执行锁、代次与断线失效约束绑定明确运行目标，保留旧 Flutter sessionId 兼容。
- [x] P01-T04：用生产 IPC/Host 集成补路由、错误来源、歧义和迟到结果回归，不能仅 mock NetworkHost 自证。
- [x] P01-T05：同步架构、MCP 描述/Prompt/指南/协议以及本阶段验收报告。

主要落点：`src/extension.ts`、`src/mcp/`、`src/project.ts`、`src/scene-controller.ts`；新增 runtime 接口的具体目录在实现时记录。不把整个 Workbench 一次性重写作为前提。

## 固定验收标准

| ID      | 必需预期                                                                                                                                 | 验证方式                                 |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| P01-A01 | 存在类型化的运行目标、代次与能力接口；公共接口不暴露 Dart RPC、Playwright Page 或私有浏览器对象                                          | 类型检查与接口依赖检查                   |
| P01-A02 | VM 与代理各有一条不同的哨兵请求；从真实 MCP IPC 调 get_requests/get_request 分别只返回目标来源，与同目标工作台一致，查询失败不回退另一库 | 扩展集成、MCP 协议回归                   |
| P01-A03 | 在代理模式切换 HTTP capture 与 Scene Mock 时，实际代理记录/规则状态和 MCP 返回一致，不误操作 VM；停用 Mock 后可继续采集                  | 生产 Host 集成，真实流量在 phase-02 复验 |
| P01-A04 | 同项目两个运行目标及不同项目同路径规则的激活、历史、临时状态互不改变；切换工作台选择不能重定向已启动运行                                 | 状态/锁集成及反例                        |
| P01-A05 | 多候选、失效代次和已断开目标在副作用前明确失败，迟到响应不复活旧目标；无自动重放                                                         | IPC 竞态与计数断言                       |
| P01-A06 | 旧 Flutter sessionId、Key 选择器、Scene v2 读写/展开、默认连接和已有设备锁行为保持兼容；未新增 Web 时不准备浏览器                        | 现有相关单元、协议与工作台回归           |
| P01-A07 | 调整的 MCP 能力具有一致 schema、描述、同名 Prompt、能力路由及离线指南；离线读取不创建项目状态或启动进程                                  | guide/transport 协议与副作用计数         |

执行 typecheck、build、相关 format/diff 检查；相关用例包含 extension、mcp-network、mcp-transport、mcp-guide、project、scene-runtime、workflows、test-network。工作台变化运行对应 UI spec。命令以实际存在的文件为准。

交付 `evidence/phase-01.md`，全部条款通过才能进入 phase-02。报告明确本阶段是适配层与路由回归，尚未完成真实浏览器代理验收。
