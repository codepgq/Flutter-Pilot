# 0.0.3：业务 WebSocket 采集与实验性 Mock

> 本页为对应旧版本的历史功能与验收记录，其中独立 Mock 开关、旧规则文件及手动恢复步骤不适用于当前源码。当前统一使用 `.flutter-pilot/scenes.json` 和场景激活/停用，重连后恢复激活场景；请按 [当前场景使用说明](../README.md#mock-场景) 与 [MCP 指南](mcp.md) 操作。下文设备结果仅证明历史版本的验证范围。

WebSocket Tab 展示 Flutter App 与业务服务器的连接和双向消息。它复用“连接与诊断”里的 VM Service 连接；业务 WebSocket 地址与 VM 调试地址用途不同，业务地址不填入 VM 输入框。

## 使用步骤

1. 按原有方式 Debug 运行 Flutter App，在“连接与诊断”连接本次 VM WS。
2. 打开 **WebSocket** Tab，点击 **开启 WS 采集**。该操作在兼容的 Dart 运行时中安装消息处理器，不修改应用源码、adapter 或 TLS。默认不修改业务消息。
3. 在连接列表选择业务连接，查看 App → 服务端和服务端 → App 的消息。点击消息查看原文、JSON 格式化、原始与生效内容，并复制正文。二进制用 Base64 展示，超限正文显示截断，二者只读。
4. 需要修改消息时单独开启 **WS Mock**。这个开关与 Dio Mock 相互独立，必须先开启 WS 采集。
5. 在“WS 规则”创建规则，按完整 URL 通配模式、可选收发方向及文本包含条件匹配，动作选择整条替换或丢弃。JSON 作为文本保存，不支持 JSON 字段路径。最高优先级首条规则生效，同优先级按列表顺序。
6. 在消息页选择在线且已接入的连接，编辑一条文本或 JSON，点击模拟推送。消息直接进入 App 接收链路，标记为模拟推送，不发送到真实服务器，也不再执行自动规则。

关闭 Tab 或工作台不停止后台采集和已开启的 WS Mock。关闭采集会关闭 WS Mock 并恢复原处理器。正常断开 VM 会尝试立即卸载；意外断开时，旧处理器最长约 15 秒后旁路，重新接入前有最多 16 秒冷却。重新连接 VM 后采集和 Mock 默认关闭，需要手动开启。

## 连接身份和规则文件

运行时连接 ID 包含本次采集会话、Isolate 和连接身份；同地址重连会产生新连接。推送只作用于明确选中的当前连接，不自动转发到同址新连接。

运行时对象没有完整 URL。只有 HTTP Upgrade 握手的 Isolate、本地端口、远端地址和端口能够唯一关联时，才显示完整 URL；否则显示远端地址及“URL 未知”。URL 未知不能命中 URL 规则，包括 `*`。此时可创建仅当前连接有效的临时规则；关闭采集或断开 VM 后清除，不写入项目文件。

持久规则使用项目目录 `.flutter-pilot/ws-rules.json`，独立于 HTTP `.flutter-pilot/rules.json`：

```json
{
  "version": 1,
  "rules": [
    {
      "id": "example-ws-price",
      "name": "模拟行情",
      "enabled": false,
      "priority": 10,
      "match": {
        "url": "wss://example.test/stream*",
        "direction": "inbound",
        "contains": "price"
      },
      "action": {
        "type": "replace",
        "text": "{\"price\":123}"
      }
    }
  ]
}
```

URL 通配支持 `*` 和 `?`，匹配完整地址。丢弃动作使用 `{ "type": "drop" }`，不带 `text`。外部编辑规则后先点击“连接与诊断 → 读取项目文件”；插件拒绝用旧内存规则覆盖外部修改。规则文件非法时保留原文件并显示错误。

## 存储和边界

- WS 消息与连接保存在项目 UUID 加工作区目录隔离的 IDE 私有 `ws-history.sqlite3`，不依赖代理引擎。VM 认证地址不写入项目文件。
- 沿用项目保留天数与记录条数设置。单条正文记录上限为 `min(maxBodyBytes, 256 KiB)`；超限消息不执行修改或丢弃，实际传输内容保持完整。消息历史保存原始和生效内容，不随规则编辑改变。
- App 事件队列和扩展写入队列均有上限；过载显示遗漏计数，不等待 IDE RPC 或阻塞业务链路。页面只传摘要，详情按需读取。
- VM 已识别的新 WS 握手归入连接详情，不写入 HTTP API 目录；旧 VM HTTP 事实保留，可识别的旧握手补充展示，不重新计算旧目录累计次数。代理 HTTP 握手记录沿用旧行为，本轮不实现代理 WS 拦截。
- URL 关联会开启 SDK 网络 profiling，App 内 HTTP 正文缓存可能增长；本地历史保留上限不等于 SDK 缓存上限。关闭 WS 采集后按 HTTP/Dio 采集需要恢复本插件拥有的开关，不自动清空其他 DevTools 数据。
- 当前是 Dart Debug/JIT 私有结构实验功能，探测失败的连接保持原样。新建连接在周期扫描前的消息不能补抓或 Mock；已有连接可以接入，但不保证恢复之前的 URL 或消息。
- 支持目标为 `dart:io` 及实际走该实现的包装库。原生插件、WebView、浏览器、Profile/AOT/Release、自定义 WS 实现和 Socket.IO 专用协议不在首版承诺范围。二进制和 ping/pong 不执行文本规则。
- 首版不提供本地 WS 服务端、定时推送、自动协议应答或代理 WS 拦截。
