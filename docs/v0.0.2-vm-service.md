# 0.0.2：通过 Flutter VM WS 零源码采集与运行时 Mock

## 可行性结论

只提供 Flutter VM Service 的 WebSocket 地址，可以在受支持的 Debug 应用中采集 HTTP API；也可以在用户主动开启后，通过 VM 的对象发现与表达式求值，给已存在的 Dio 安装运行时拦截器，完成本地 Mock、请求修改、响应修改和转发。**这个结论已通过真实 Flutter iOS 模拟器验证，不只是技术推测。**

两者需要区分：VM 的 HTTP profiling 接口本身只提供观察能力。Mock 使用 Debug/JIT 的 `getInstances` / `evaluate` 运行时能力，在应用内存中安装本插件的 Dio 拦截器，不写入应用源码、不替换 HTTP adapter，也不安装证书。因此它是实验性运行时功能，不能承诺所有网络库或所有 Dio 拦截链均可覆盖。

VM WS 是默认且优先推荐的接入方式，代理作为 VM 不适用或需要手动断点时的备用方案。新工作区不会自动初始化或启动代理，即使存在可用引擎缓存；已有工作区沿用保存的模式，旧版没有 mode 字段的连接配置保留代理路线。开启 VM 连接默认仅记录，不改变接口；运行时 Mock 必须另行开启。两种模式共用规则，保存时也同步仍在运行的旧代理；历史和 API 目录分别保存。关闭运行时 Mock 只移除 VM 拦截器，旧代理需单独停止。

## 安装与操作

本版本按用户指定使用 `0.0.2`，比之前已安装的 `0.1.0` 小；请使用强制覆盖安装：

```sh
npm ci
npm run package
cursor --install-extension artifacts/flutter-api-mocks-0.0.2.vsix --force
```

VS Code 将 `cursor` 换为 `code`。安装后重新加载窗口，在受信任的 Flutter 工作区执行 **Flutter API Mocks: 打开工作台**。

1. 用项目原来的入口以 **Debug** 运行 Flutter 应用。获取 IDE 调试输出或 Flutter 工具提供的本次 VM Service WS 地址，形式类似 `ws://127.0.0.1:<port>/<本次认证路径>/ws`。请保留认证路径，不要使用 DevTools 网页或业务 WebSocket 地址。
   如果工具输出的是 `http://.../<认证路径>/`，将协议改为 `ws://` 并在末尾追加 `ws`；`https://` 对应 `wss://`，保留完整认证路径。
2. 打开 **连接与诊断 → VM 连接**，自动发现 IDE 内 Flutter Debug 会话；唯一会话自动连接，多个会话手动选择。也可输入 **VM WebSocket 地址**，点击 **连接并记录**。输入框提交后清空；状态仅显示 endpoint host，不显示认证路径。VM WS 不保存到磁盘。
3. 在应用里触发请求，到 **API 与历史** 查看。采集受支持的 `dart:io` HTTP 请求，不需要创建规则、代理引擎或 CA。连接前没有被 profiling 采集的请求无法补录。
4. 需要修改接口时，开启 **开启运行时 Dio Mock**。等待“已接入 Dio”出现有效数量；没有实例时，先让应用初始化网络层，再点 **重新发现并同步**。
5. 打开 **Mock 规则**，创建或从历史生成规则。草稿默认禁用，检查后启用并保存；确认同步成功，再次在应用内触发请求。可以直接 Mock、修改请求、修改响应或转发；VM 不支持手动断点。
6. 在详情查看 Request / Response、规则命中及修改快照。目录和历史倒序，目录可折叠；文本自动尝试 JSON，也可切换原文和复制。
7. 关闭工作台后，VM 会话继续采集，已开启的运行时 Mock 也继续工作。使用 **关闭 Mock** 恢复观察模式，或 **断开连接** 结束会话。Hot Restart 后会周期性重发现新的 Isolate 与 Dio；完整停止后新调试会话可自动连接；手动断开后需显式重新连接。自动发现边界见 [说明](vm-auto-discovery.md)。

VM 历史查询不依赖代理引擎。即使引擎尚未安装，也可打开 VM 模式查看已保存历史和 API 目录。

### 连接状态与 DDS 跳转

连接卡使用真实会话状态：连接中禁用输入与重复提交，成功后突出显示“已连接 · 当前端点”和后台记录状态，地址输入保持禁用，只保留断开操作。更换地址需先断开；断开或失败后清除活动端点和 Isolate / Dio 数量，不能把上次连接的端口当成当前连接。后台同样拒绝重复连接，避免双击或排队消息卸载已有 Mock。

Flutter 原始 VM WebSocket 可能返回 HTTP 302，将连接交给 DDS。插件最多跟随两次字面本机地址（`127.0.0.1`、`::1`、`localhost`）之间的跳转，保留目标认证路径和查询参数，并使用 WS 协议连接；拒绝外部主机、用户信息、片段和 WSS 降级。其他情况按提示提供最终 DDS WS。连接成功后显示实际 DDS 端点，不展示完整认证地址。

连接失败提示区分端口拒绝、超时、认证拒绝、路径不存在、受限跳转及初始化失败。App 重新运行后端口和认证路径可能变化，需复制本次完整地址。初始化过程中 socket 断开时，不会再把状态回写为已连接。

### 从旧代理路线切换

界面切换模式不会修改已运行应用的网络配置，也不会自动删除 helper。

先停止当前 Flutter 调试，去掉 `API_MOCK_PROXY` 参数，切回项目原启动项重新运行 App，再停止旧代理并连接 VM。旧代理仍在运行时，VM 页会显示提醒及 **停止旧代理**。不要先停止引擎，却让旧 App 继续指向代理；这种状态仍可能导致应用断网。

VM 转发由 App 的 Dio 发起，`127.0.0.1` 指设备自身。代理模式转发由电脑发起，`127.0.0.1` 指电脑。访问本地服务时应按模拟器 / 真机网络选择正确地址，不能直接照搬代理模式的目标 URL。

## 工作方式与规则边界

- 默认观察使用 `ext.dart.io.httpEnableTimelineLogging`、`getHttpProfile` 和 `getHttpProfileRequest`，按周期读取多个 Isolate，适配 Hot Restart。插件恢复自己改变的 profiling 开关状态，不清理其他 DevTools 的网络记录。
- 开启 Mock 后，查找已存在的 Dio 并安装 `InterceptorsWrapper`。成功接入后改用 Dio 事件采集，避免同时记录 SDK 与注入数据；未找到实例时继续观察并提示。
- 规则仍按原始请求匹配；每阶段执行最高优先级的首条，同优先级按列表顺序。本地 Mock 继续进入响应修改流程。跨源转发默认移除源站凭证，可在规则中显式设置目标凭证。
- 运行时只在明确修改状态码时重新按 Dio `validateStatus` 分类；空规则或仅修改正文保留应用原有业务错误分类。服务端 `badResponse` 可以由规则修改状态后恢复，连接错误不会伪装成服务端响应。
- VM 模式数据是 Dio 层快照，其他应用拦截器仍可能继续加工。应用自己的拦截器若提前 `resolve/reject` 且不继续调用后续拦截器，可能绕过本插件追加的拦截器。
- 新 Dio 周期性发现，每个 Isolate 最多接入 128 个；超过时提示。实例创建后首次请求可能早于扫描，应等待接入或手动重新发现。不能保证覆盖瞬时创建、使用后立即释放的所有实例。
- 注入模式单正文保存 / 编辑上限为 **256 KiB**，已启用规则快照总量上限 **2 MiB**；上传、流、自定义正文不主动读取，二进制保持直通。非 JSON 的 `List<int>` 与非文本 Content-Type 正文只读，改头不能绕过正文保护；显式 JSON 数字数组仍可编辑。默认观察的本地正文保存受 `maxBodyBytes` 控制，截断标识不等于真实网络数据被截断。
- SDK profiling 会在 App 内保存额外数据，本插件没有强制限制该 SDK 缓存容量。本地 SQLite 的 7 天 / 10,000 条限制不约束 App 内缓存；长时间大量采集可能增加应用内存，结束后及时断开。

## 生命周期与恢复

正常关闭 Mock / 断开时，插件尝试立即卸载自己的运行时拦截器，恢复观察或结束采集。规则同步与停用串行执行，避免停用后旧异步扫描再次安装。

运行时拦截器使用 **15 秒租约**，会话以心跳续期。IDE 崩溃或连接意外断开时，租约到期后不再接管新请求；已发出去的请求改写无法撤回，停用后尚未返回的请求不再应用插件响应修改。不能把异常断开解释为所有在途请求即时恢复。

意外断开后有约 **16 秒冷却**，可以立即重连观察，但需要等待旧租约到期才允许重新开启 Mock；界面显示剩余等待时间。正常显式关闭 / 断开且卸载成功时不受该冷却限制；无法确认卸载时同样等待旧租约。

SDK profiling 开关无法在连接已断开时立即关闭。恢复失败会明确告警，并在内存中保留归属；同一 VM 的 PID、启动时间与 Isolate 一致时，重新连接后再正常断开可完成恢复。IDE 崩溃、进程身份无法确认时，请 Hot Restart；不会自动清空其他调试工具的网络缓存。

VM WS 能执行调试操作，应只连接受信任、当前开发中的应用，不公开端口或共享认证路径。请求历史也可能包含凭证，分享前需自行脱敏。

## 实际验证与复现

本轮真实 Flutter 验证环境：**iPhone 18 Pro / iOS 27.2 模拟器，Flutter Debug**。八项实际检查通过：

1. 仅连接 VM，采集真实 POST 请求与响应正文。
2. 已存在 Dio 的 HTTPS 请求命中本地 Mock，不访问上游，无需 CA。
3. 修改请求方法、query、header、body，以及响应状态。
4. 将真实上游 503 修改为 200，并在 Dio 调用端收到修改结果。
5. Hot Restart 后重发现新 Isolate 并重新接入规则。
6. 关闭 / 重新开启 Mock，验证直通与规则恢复。
7. 观察模式下异常断线，重新连接同一 VM 后再正常断开，SDK 网络采集开关恢复关闭。
8. 应用入口文件 SHA-256 保持不变；没有代理、helper 或 CA。

纯 Dart 真实 VM 集成实测 Dio **5.9.0 / 5.10.0 / 5.11.1** 各 **21 项全部通过**，覆盖多 Dio、规则更新、Mock 响应后修改、流响应状态一致、请求修改、跨源转发凭证清理、错误分类、失效 JSON 规则诊断、网络错误历史、主动卸载和租约到期旁路。最新回归项数及 IDE 测试结论统一记录于 [验收记录](validation.md)，不沿用旧代理统计。

复现前安装 Flutter / Dart、仓库依赖并为示例执行 `flutter pub get`：

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run test:ui
npm run test:vm
VM_FLUTTER_DEVICE=YOUR_BOOTED_IOS_SIMULATOR_ID npm run test:vm:flutter
npm run test:ide:vm
API_MOCK_TEST_IDE=cursor npm run test:ide:vm
```

真实 IDE smoke 使用合成 VM JSON-RPC 服务和内部消息入口，只验证扩展宿主与生命周期；工作台交互由 Playwright 覆盖，真实 Flutter Mock 由独立模拟器测试覆盖。

`test:vm` 默认使用 `examples/flutter/.dart_tool/package_config.json`，可通过 `VM_PACKAGE_CONFIG` 指定另一套已安装 Dio 的 package config，以复测版本差异；`DART` 和 `FLUTTER` 可指定对应可执行文件。Flutter smoke 会临时运行应用和本地测试服务，结束后清理；报告写入忽略的 `artifacts/vm-flutter-validation.json`。报告可能包含本机设备 ID，分享时需脱敏，不提交原始认证数据。

以下尚未通过本轮实际验收：VM 路线在 Android 模拟器 / 真机、iOS 真机上的运行，Profile / AOT / Release 的注入能力，EXIO 真实登录链路，以及所有自定义网络适配器 / 拦截器组合。EXIO 的 MFA 代理超时仍在项目问题记录中，本次独立示例通过不代表该问题已修复。
